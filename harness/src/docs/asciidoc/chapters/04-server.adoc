.A plain text response
[source,java]
----
include::{booktests}/ServerTests.java[tag=respond,indent=0]
----

The server listens on the loopback address, on a port the operating system picks, so tests never collide on a port and nothing outside the machine can reach the server.
It handles each request on a virtual thread.
Every context created in the routes is instrumented: each request is a server span named after the method and the context path, `GET /hello`, with the HTTP semantic convention attributes, and the span is current while the handler runs.

The routes receive the server as an `HttpServer` for creating contexts.
Starting, stopping and the executor belong to the harness, and the server refuses them.

=== The server

The body receives a `Server`:

[cols="2,5",options="header"]
|===
| Method | Returns
| `base()` | `+http://127.0.0.1:<port>/+`
| `port()` | The port
| `uri(path)` | The base resolved against a path, with or without a leading slash
| `get(path)` | A `GET` of the path, with the body as a string
| `send(request, bodyHandler)` | The response to any request, sent in a client span
| `client()` | The `HttpClient` behind `get` and `send`
| `span()` | The span the body runs in
| `openTelemetry()` | The instance the server and the client report to
| `propagationHeaders(context)` | The headers that carry a context, for clients the harness does not own
| `httpServer()` | The JDK server itself
|===
