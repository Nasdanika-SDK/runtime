== Navigating a diagram

A program that reads a diagram walks it, searches it, follows its connections and folds it into a result.
The API has a way to do each.

=== Walking the containment

Pages contain a model, the model a root, the root layers, and layers their elements.
A loop over that structure is the most direct way to read a diagram:

The layer with ID `1` is the default layer that Draw.io creates on every page; the _Notes_ layer of the running example has the ID `notes`.
Elements come in the order of the file, which is the z-order of the page: what was drawn later is on top.
`getElements()` returns the elements directly in a layer; a node's own `getElements()` returns what it contains, because a node is a layer.

=== Connection base

Draw.io puts a connection in a layer, or in the node that contains both of its ends.
For many purposes that parent is not the logical one.
In a diagram of systems, a connection from the Internet Banking System to the mainframe is something the Internet Banking System does, so it belongs under its *source*.
In a mind map, where arrows point from a topic to its parent, a connection belongs under its *target*.

`ConnectionBase` says which:

* `PARENT`, the default, keeps connections where the file puts them;
* `SOURCE` makes each connection a child of its source node;
* `TARGET` makes each connection a child of its target node.
