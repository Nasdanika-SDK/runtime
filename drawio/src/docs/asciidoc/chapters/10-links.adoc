[#links]
== Links between pages, elements and documents

Links are how a diagram gets levels of detail: an element on a system context page links to the page that shows what is inside it.
Draw.io links an element to a URL or to a page of the same file.
The API reads those links, and extends them to elements, and to pages and elements of other documents, so a set of files becomes one network of diagrams.

=== Link syntax

Draw.io writes a link to a page as `data:page/id,<page ID>`.
The API accepts four forms, two of which are Draw.io's own:

[cols="3,4",options="header"]
|===
| Link | Points to

| `data:page/id,<page>`
| A page by ID. Draw.io writes this form when you choose a page in the _Edit Link_ dialog.

| `data:page/name,<page>`
| A page by name, URL-encoded: `data:page/name,System+Context`.

| `data:element/id,<element>`
| An element by ID.

| `data:element/name,<element>`
| An element by the text of its label, HTML removed, URL-encoded.
|===

The part after the comma can say where to look:

* `<document>#<page>` for a page in another document, where `<document>` is a URI resolved against the URI of the linking document: `data:page/name,overview.drawio#Page+2`;
* `[<document>#]<page selector>/<element>` for an element on another page, where the page selector is `id,<page ID>` or `name,<page name>`: `data:element/id,id,system-context/ibs`, `data:element/name,overview.drawio#name,Page+2/Linked`.

An element link without a page selector looks on the linking element's own page.
Element links and links to other documents are an extension: Draw.io itself opens them as URLs, so they work in programs built on the API and not when clicked in the editor or the viewer.

=== Resolving links

`getLinkTarget()` returns what a link points to: a `Page` or a `ModelElement`, both `LinkTarget`s.
`isTargetLink()` says whether the link is in one of the four forms at all; a link to a web page returns `false`, and its target is `null`.

<3> The Mainframe Banking System on the _Containers_ page links to its namesake on the _System Context_ page, by page name and element ID.

A link that cannot be resolved, to a page or an element that does not exist, throws a `ConfigurationException` with a marker that names the page and the element that has the link.
That makes checking a diagram's links a one-line test: visit every element with `isTargetLink()` and call `getLinkTarget()`.

=== Logical URIs

The URIs in links do not have to be locations.
A context's `openStream(URI)` opens every linked document, so it can map logical URIs to wherever the documents are: a classpath, a Maven artifact, a GitLab repository read through its API without cloning, or a different location for each environment:

With placeholders on, a link can also depend on the context: `data:page/name,%release%/overview.drawio#Overview`, with `release` supplied by the context, links each release's diagram to that release's overview.

=== Element URIs

`getURI()` returns a URI for every element: the document's URI with a fragment of the IDs from the page down, so it identifies the element across documents.
`resolveURI(base, provider, connectionBase)` builds URIs of your own, from a property of each element resolved against its logical parent's, with the connection base of <<navigating>> deciding whether a connection's parent is its layer, its source or its target.
That is how a diagram maps to a hierarchy of resources, such as the pages of a documentation site, or the paths of an API.
