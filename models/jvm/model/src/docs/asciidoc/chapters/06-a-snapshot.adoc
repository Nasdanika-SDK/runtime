For the boot layer of this module's own tests, the answer for the model is:

[cols="2,3",options="header"]
|===
| Module | Reads without requiring
| `org.nasdanika.sdk.runtime.models.jvm` | `org.eclipse.emf.common`, `org.eclipse.emf.ecore`
|===

That is `requires transitive` at work: the JVM model requires the core model, and the core model requires EMF transitively.
In a larger assembly the answer gets more interesting.
EMF and many other libraries are automatic modules, jars without a module descriptor, and the module system gives a module that reads one automatic module readability of all of them.
In the assembly of an example in the Nasdanika SDK Runtime book, the core model, which requires only EMF and `java.scripting`, reads OpenTelemetry and a JSON library for exactly that reason.
No build file says so, and a snapshot shows it in the first query anyone runs.
