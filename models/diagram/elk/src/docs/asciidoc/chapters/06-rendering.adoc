[#rendering]
== Rendering with React Flow and Draw.io

A laid out diagram is geometry: bounds, routes and label positions.
The demos render it twice, with React Flow in the browser and with Draw.io, and both show the layout as ELK computed it.

=== React Flow

React Flow draws nodes and edges in the browser.
By default it routes edges itself, between handles on the nodes; here it should not, because ELK already routed them.
So the edges are of a custom type that draws ELK's route and labels as they are.

=== Draw.io

The Draw.io renderer writes a Draw.io document with the runtime's Draw.io API:

<1> A Draw.io node is a layer, so packages contain classes as the diagram does, with bounds relative to the container.
<2> Ports become Draw.io connection points at the same relative location.

.Connections, waypoints and end labels
[source,java]
----
include::{booktests}/DrawioRenderer.java[tag=connection,indent=0]
----
<1> A connection attached to a node gets a connection point where ELK's route touches the node, so Draw.io starts and ends it exactly there.
<2> The rest of the route becomes Draw.io's waypoints.
<3> Draw.io positions an edge label along the edge, from -1 at the source to 1 at the target. A tail label is anchored at the source end, a head label at the target end, a center label at the middle.
<4> The offset from the anchor puts the label where ELK placed it. Labels stay attached to their edge when someone moves it in Draw.io.

The document opens in Draw.io as laid out, and is a normal Draw.io document from then on: people can move boxes, restyle them, and add what a generator could not know.
