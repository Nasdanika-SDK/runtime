[#getting-started]
== Getting started

The model is an EMF model, defined in Xcore and generated into Java when the runtime is built.

=== Adding the model

The runtime's models have a bill of materials, `org.nasdanika.sdk.runtime.models:bom`, which manages their versions.
Import it in `dependencyManagement`, and depend on `{group-id}:{artifact-id}` without a version.

The model is a named Java module:

.The module declaration of the SVG model
[source,java]
----
include::{runtime-root}/models/svg/model/src/main/java/module-info.java[tag=module,indent=0]
----

It requires the runtime's `common` module transitively, which brings EMF with it, and EMF's XML resource.
It provides its `EPackage`, a contents handler for `.svg` resources, and a resource set contributor that registers the resource factory for the extension.

=== Writing and reading without a resource set

`SvgFormat` writes an `svg` element to a stream or a string, and reads one from a stream.
That is all a generator needs (<<building>>).

=== In a resource set

`NasdanikaResourceSet.createAndConfigure()` creates a resource set and lets every module on the module path contribute to it.
With the model on the module path, a `.svg` file loads as its root `Svg` element, and a resource with one saves as SVG.

The resource factory reads the dots in a file name as qualifiers, right to left, and asks for a contents handler for each, starting with the leftmost.
The SVG model's handler answers for the last qualifier, `svg`, so a more specific one wins for a name with more: `system.drawio.svg` loads as a Draw.io document when the runtime's Draw.io model is on the module path, from the document that Draw.io embeds in its SVG export.

=== What the build does

The Xcore definition is in `src/main/resources/org/nasdanika/sdk/runtime/models/svg/svg.xcore`.
Maven generates the Java sources into `src-gen` with the Xtext Maven plugin.
The generated API is in three packages: the interfaces in `org.nasdanika.sdk.runtime.models.svg`, their implementations in `impl`, and the switch and adapter factory in `util`.
`SvgFormat` and the contents handler are hand-written, in `resource`; the services are in `services`.
