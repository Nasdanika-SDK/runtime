== The TypeScript model

[cols="1,4",options="header"]
|===
| Area | Classes
| Base | `TypeScriptElement`, a core model `NamedElement`
| Packaging | `Package`, `Module`
| Imports | `Import`, `ImportBinding`, `ImportKind`
| Type references | `TypeReference`, `PrimitiveTypeReference`, `NamedTypeReference`, `ArrayTypeReference`, `UnionTypeReference`, `IntersectionTypeReference`, `LiteralTypeReference`, `TypeLiteralReference`, `FunctionTypeReference`, `OpaqueTypeReference`
| Declarations | `Declaration`, `InterfaceDeclaration`, `ClassDeclaration`, `TypeAliasDeclaration`, `EnumDeclaration`, `EnumMember`, `FunctionDeclaration`, `VariableDeclaration`
| Signatures | `Callable`, `Parameter`, `TypeParameter`, `CodeBlock`
| Members | `Member`, `Property`, `Method`, `Constructor`, `Accessor`, `OpaqueMember`
|===

A `Package` is deliberately thin: a scoped `packageName`, a `version`, a description, a license, the module type, dependencies, and its `modules`, enough to write `package.json` and lay out files.
It is there because a generator that writes modules but not the package around them leaves the last mile to a script, and that script is where drift starts.

A `Module` has a `path` in the package, `declarationOnly` for a `.d.ts`, a header, its authored `imports`, and its `declarations`.
A `Declaration` may be `exported` or `ambient`.

`Callable` is the supertype of functions, methods, constructors and accessors, so the generator writes one signature routine for all four: type parameters, parameters, a return type, a body, `async` and `generator`.

A `NamedTypeReference` points at a declaration of the model through `target`, or names a type the model does not own by `qualifiedName` and `moduleSpecifier`, with `typeArguments`.
The target is what the import resolver follows.

=== The generator

`Generator` writes a `Package` or a `Module` to a `GenericVolume<String>`, the runtime's abstraction of a tree of files, here of text: a directory adapted to text, an in-memory volume for a test, or any other volume.
For a package it writes `package.json`, `tsconfig.json`, and a file per module under `src`; missing directories are created through the volume.
`generate(module)` returns one module as a string.

The module's `BankTests` generate a larger package that uses every construct of the model into `target/bank`.
It compiles with `tsc` under `strict` and `--verbatimModuleSyntax`, which turns a wrong decision between a type and a value import into a compile error, in a step outside the Maven build (<<building-this-book>>).
