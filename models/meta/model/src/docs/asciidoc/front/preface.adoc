== Preface

This book is about Meta, the language-neutral type system of the Nasdanika SDK Runtime: a micro-model of typed domain models, with packages, classes, features, operations and the type references between them, in about twenty classifiers.
A vocabulary is written down once in Meta, with its documentation as structure, and projected to whatever its consumers need: a glossary or a PDF for people, a dynamic Ecore package for tools, TypeScript for browsers, JSON Schema for the tools of agents.
Developers write it in Meta's text syntax, `.nmeta` files; the people who own the words will write it in the spreadsheets, diagrams and Markdown they already use.

The first part of the book is the why: why one definition should not live in many formats, why documentation should be structure, what Meta leaves out on purpose, and why there is no server.
The second part is the how, for Java developers: a vocabulary of a library, built in Java; the vocabulary of a bank, with its customers, products, accounts, transactions and statements, written in the text syntax and loaded through a resource set; and projections of both to a glossary and to Ecore.
The third says what comes next: the formats vocabularies will be authored and published in, with who each is for, flattening, and vocabularies that vary by where and when they apply.

=== Who this book is for

*Architects and modelers* who keep a domain's vocabulary, today in spreadsheets, wiki tables and schemas that disagree, and want it in one place with the types and the documentation generated from it.

*Developers* who write vocabularies in the text syntax, and projections from a vocabulary to code, schemas, documentation, or the context of an agent.

*Business owners of a vocabulary*, who will read <<why>> and <<formats>>: what they will author in, and what they will get back.

=== A book that stands on its own

This book is one of the Nasdanika Zephyr Books: in-depth manuals, one per module of the Nasdanika SDK Runtime, in the manner of IBM Redbooks.
You do not need any other book of the series, or the Nasdanika SDK Runtime book, to read this one: where the books touch, this one repeats what you need.

The series is named after the Bootswatch theme it is styled with, Zephyr, and has nothing to do with the Zephyr real-time operating system or with SmartBear's Zephyr test management.

=== What you need

* *A JDK for Java 25* and *Maven 3.9.16 or later*.
* The model's Java module is `org.nasdanika.sdk.runtime.models.meta`, its Maven coordinates are `{group-id}:{artifact-id}:{runtime-version}`, and its namespace URI is `{nsuri}`.
* Some familiarity with EMF helps in part two: an EMF model is a set of Java interfaces generated from a metamodel, with containment, references, reflection and persistence for free. Meta is itself an EMF model, and one of its projections is to Ecore, EMF's metamodel.

=== Conventions

* *Every listing is included from a test* of the module and compiled and run when the book is built. Callouts, such as <1>, explain the lines they mark.
* *Status labels* mark what this edition does not have yet: [.planned]#PLANNED# for designed but not built, [.sketch]#SKETCH# for partly built.
* *Voice.* I write in the first person.

Editor's notes record inconsistencies between the model and its documentation found while writing. They are shown in builds for the author and left out of published editions.

This book replaces the model's readme, `models/meta/model/doc/readme.md`, which is deleted. The readme placed Meta in a model tower with floors and an occupancy model; the runtime has neither yet, and this book describes what it has, with the rest as planned. The Xcore's comments still say "nxcore" for the core model.

The example in the header of `Meta.g4` throws `Error`, which it does not declare, so the reader reports an unknown type; the tests declare it. The grammar's header says a facet is attached to its element as a contained object; the core model's `facets` feature is commented out, so the reader records facets as annotations until it is not (<<facets>>).
