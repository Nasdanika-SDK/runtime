== Mix-ins

A picocli mix-in is a reusable set of options: a class with `@Option` fields, mixed into a command with `@Mixin` or `addMixin`.
In this module, mix-ins can also be contributed: a factory adds a mix-in to the commands it matches, the way a command factory places a command.

=== Mix-ins by type

The other direction is the command choosing its mix-ins.
`@MixIns` on a field, or on a method taking one parameter, says what mix-ins a command accepts, by the member's generic type, as `@SubCommand` does for sub-commands; and the accepted mix-ins are injected into the member.

A member typed as an array, a `List`, a `Collection`, an `Iterable` or a `Set` takes all the accepted mix-ins; any other member takes the first.

=== Matching mix-ins

A mix-in factory adds its mix-in to a command when:

* the mix-in takes the command through a `@Parent` member, matched by type;
* the command accepts the mix-in through a `@MixIns` member, matched by type; or
* the command's class, or a superclass, is annotated with `@MixIns` listing types, and the mix-in is adaptable to one of them. Classes cannot carry type arguments, so this form matches raw types only, and nothing is injected: the command finds its mix-ins through picocli, `spec.mixins()`.

=== Mix-ins with fields

Mix-ins a command always has need no factory: a picocli `@Mixin` field is enough, and the runtime's `ResourceSetMixIn` and `PropertiesMixIn` are used that way (<<runtime-commands>>).
Contribute a mix-in when the command should not have to know it: an option that a module adds to every command that supplies a model, for example.

=== Mix-in or command

The previous generation of Nasdanika relied on mix-ins for separation of concerns, and it led to option explosion and name collisions: every concern added options to every command.
A sub-command is often the better unit: it has its own options, it appears only where it applies, and it composes into pipelines.
I usually write the base of a concern as a class without `@Command`, so it can be mixed in, and a command that extends it, so it can be a step of a pipeline; which one to contribute is a judgement call.
